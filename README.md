# Dog&Dog Invent+ - Инструкция по приложению

Это приложение для управления инвентаризацией, созданное для "Dog&Dog". Оно интегрировано с внешней системой "Poster" для синхронизации данных и использует Firebase для реализации бизнес-логики, такой как рабочие процессы утверждения.

## Основные технологии

*   **Фронтенд:** Next.js (с App Router), React, TypeScript
*   **UI:** shadcn/ui, Tailwind CSS
*   **Бэкенд и База данных:** Firebase (Firestore, Authentication)
*   **Внешние интеграции:** Poster API

---

## Реализованный функционал

### 1. Система навигации

Приложение имеет полноценную систему навигации, которая адаптируется под мобильные устройства.

*   **Основные разделы:**
    *   **Поставки (`/supplies`):** Самый функциональный раздел на данный момент.
    *   **Списания (`/write-offs`):** Страница-заглушка.
    *   **Перемещения (`/transfers`):** Страница-заглушка.
    *   **Инвентаризация (`/inventory`):** Страница-заглушка.
    *   **Настройки (`/settings`):** Раздел для управления приложением.

### 2. Управление поставками (`/supplies`)

Это ядро текущей функциональности. Здесь реализован полный цикл создания и утверждения заявок на поставку.

*   **Создание заявки на поставку:**
    *   По кнопке "Добавить поставку" открывается диалоговое окно.
    *   В форме можно выбрать **поставщика**, **склад** и **ответственного сотрудника**. Данные о поставщиках и складах подгружаются напрямую из Poster API.
    *   Можно добавлять один или несколько **ингредиентов**, указывая их количество и цену. Список ингредиентов также синхронизирован с Poster.
    *   При отправке форма создает **заявку на утверждение** в базе данных Firestore со статусом `pending`.

*   **Процесс утверждения для администратора:**
    *   На странице "Поставки" администратор видит специальный блок **"Ожидают подтверждения"**.
    *   В этом блоке отображаются все заявки со статусом `pending`.
    *   Администратор может **Одобрить** или **Отклонить** заявку.
        *   При **одобрении**: заявка отправляется в Poster API для официальной регистрации, а ее статус в Firestore меняется на `approved`.
        *   При **отклонении**: статус заявки в Firestore меняется на `rejected`.

*   **Просмотр последних поставок:**
    *   Ниже на странице отображается таблица с последними поставками, данные для которой загружаются напрямую из Poster API.

### 3. Настройки (`/settings`)

*   **Смена темы:** Пользователь может переключаться между светлой и темной темой интерфейса.
*   **Список сотрудников:** Отображается статический список сотрудников. На данный момент это демонстрационные данные.

### 4. Интеграция с Firebase

*   **База данных Firestore:** Настроена для хранения заявок на поставку (`pendingSupplies`). Структура данных и правила безопасности определены в файлах `docs/backend.json` и `firestore.rules`.
*   **Правила безопасности:** Реализована ролевая модель:
    *   **Администраторы:** Имеют полный доступ ко всем данным.
    *   **Обычные пользователи:** Могут создавать заявки и видеть только свои транзакции.
*   **Аутентификация:** Подключена, но сам процесс входа/выхода пользователя в интерфейсе еще не реализован.

### 5. Пользовательский интерфейс

*   Все компоненты (кнопки, таблицы, диалоговые окна) построены на базе библиотеки `shadcn/ui`, что обеспечивает единый и современный внешний вид.
*   Интерфейс полностью адаптивен и корректно отображается как на десктопе, так и на мобильных устройствах.
